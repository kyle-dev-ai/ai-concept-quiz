# ADR 0010: 답 공개 카운트다운과 브라우저 음성 유사도

- Status: Accepted
- Date: 2026-08-21

## Context

이 앱의 학습 방식은 자기평가다. 사용자가 질문을 보고 스스로 설명한 뒤 `known` / `unsure` / `unknown`을 고르면, `reviewIntervalDays`가 다음 복습 시점을 정한다.

문제는 자기평가가 관대해지는 경로가 열려 있었다는 것이다. 답 공개 버튼이 언제나 눌러졌기 때문에, 질문을 보고 "아 이거 알지" 하고 곧바로 답을 열어 `known`을 고를 수 있었다. 그러면 다음 복습은 7일 뒤, 그다음은 21일, 60일로 밀린다. 입 밖으로 한 번도 내지 않은 개념이 통달한 것으로 기록된다. 대학원 구술 대비가 목적인 앱에서 이 누수는 크다.

자기평가를 대체할 채점이 필요한 것은 아니다. 필요한 것은 사용자가 자기 상태를 더 정확히 판단하도록 돕는 근거다.

## Decision

- 답 공개 버튼을 기본 10초 카운트다운 뒤에만 활성화한다. 그 시간 동안 소리 내어 설명하게 하는 것이 목적이다. 시간은 `revealDelaySeconds` prop으로 조정 가능하고 0이면 곧바로 열린다.
- 카운트다운 동안 브라우저 내장 음성 인식으로 발화를 받아적는다. 답을 열면 인식을 멈추고, 전사와 모범 답을 비교한 유사도(%)와 핵심 포인트별 적중 여부를 자기평가 버튼 위에 보여준다.
- 유사도는 글자 2-gram Dice 계수로 브라우저 안에서 계산한다(`src/domain/learning/spoken-answer.ts`). 의미 임베딩이나 LLM 채점은 쓰지 않는다. 서버가 필요해져 ADR 0001의 local-first 전제가 깨지기 때문이다.
- 이 점수는 채점이 아니라 참고값이다. 표현이 겹치는 정도만 재므로 뜻이 같아도 낱말이 다르면 낮게 나온다. 화면에 그렇게 명시하고, 자기평가 등급이나 복습 간격에 자동으로 반영하지 않는다.
- 음성 인식은 `SpeechRecognizer` port 뒤에 둔다. feature는 concrete adapter를 import하지 않는다.
- 미지원 브라우저, 마이크 권한 거부, 무음은 각각 다른 안내를 보여주고 학습은 그대로 진행된다. 음성 인식은 학습의 전제조건이 아니다.
- 전사 결과는 앱이 저장하지도 전송하지도 않는다. 다만 인식 처리 위치는 브라우저가 정하고 일부 브라우저는 음성을 자사 서버로 보내므로, 마이크를 켜는 화면에서 그 사실을 안내한다.

## Consequences

- 자기평가가 실제 발화에 근거하게 되고, 말하지 않고 넘어가는 경로가 막힌다.
- 답을 보기까지 최소 10초가 걸려 세션이 길어진다. 훑어보기용으로 쓰기는 어려워지는데, 이는 의도한 비용이다.
- 유사도는 표현 겹침만 재므로 같은 뜻을 다른 낱말로 설명하면 낮게 나온다. 사용자가 이를 오해하지 않도록 문구로 방어한다.
- Web Speech API는 표준 lib.dom 타입에 없어 adapter가 쓰는 만큼만 타입을 선언한다. 브라우저별 지원 편차는 미지원 경로로 흡수한다.
- 의미 기반 채점이 필요해지면 `SpeechRecognizer`와 `scoreSpokenAnswer` 경계는 그대로 두고 구현만 교체할 수 있다. 다만 그 시점에는 음성·텍스트 외부 전송을 다시 판단해야 한다.
